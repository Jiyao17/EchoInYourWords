00 · KVTok-v2 modified architecture (new)

KVTok-v2 keeps KVTok's Stage-1-only pooling for the Sharer cache only. The Receiver contributes an embedding lookup — never a KV cache — processed by receiver_proj + sinusoidal PE + LayerNorm. A lightweight cross-attention fusion and EIYW-v2-style calibrated output head emit Receiver-compatible soft tokens.

03 · If you want to add a module, not just tune one

--bottleneck-dim and --num-soft-tokens only reach the 15% of the translator not pinned to receiver_hidden. To meaningfully grow capacity beyond that, these are architecture edits to methods/eiyw/translator.py:

A

Widen the output head

Replace out_proj with a 2-layer MLP (1024→m→GELU→1024). Grows the single biggest block (48%) independent of K or bottleneck_dim — currently the one place with no dial at all.

translator.py:85, :164
+ ~2×m params, m=hidden size of new mid layer
B

Multi-head cross-attention

Stage 2 is effectively single-head (one shared query/key/value space). Split into H heads before the einsum, concat, project — lets different soft tokens specialize on different Sharer content.

translator.py:158–163
+ per-head out proj, ~H× small
C

Iterative refinement

Feed Stage 2's pooled output back as queries over the same 96 span tokens for a second round (perceiver-style stacking) before out_proj.

translator.py:163–164
+ 1 more attention block's worth of params per round
D

Per-layer Stage-1 pooling

span_key/span_query are shared across all 24 Sharer layers. Giving each layer its own would let pooling specialize per depth — expensive.

translator.py:67–68
+ ≈24× stage-1 cost, ~3.2M params
